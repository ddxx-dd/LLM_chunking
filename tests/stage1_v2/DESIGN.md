# processed_para 전처리 설계 (1차 + 2차, PDF·docx)

작성 2026-10-14. 시험 코드·결과는 모두 `tests/stage1_v2/`. 이 설계가 확정되면 `src/`로 옮긴다.

## 0. 원칙
1. **Docling 표준 파이프라인 + 규칙 기반 후처리만**. VLM 전체 변환은 쓰지 않는다.
2. **모든 청커가 같은 글**을 받는다(`processed_para` 하나). 문단 경계는 fixed·recursive(`\n\n`)와 ASC 문단 모드에 쓰이므로 "충분히 좋게"를 목표로 한다(완벽 X).
3. **1차 = 원본 PDF에서만 알 수 있는 정보를 남긴다**(위치, 줄, 글자 층). **2차 = 그 정보로 판단한다**. 2차 규칙은 1차를 다시 돌리지 않고 고칠 수 있어야 한다.
4. 규칙마다 **적용 건수와 지운 단어 수를 기록**하고, 지운 것은 표본을 원본 이미지와 대조해 검증한다. 한 문서만을 위한 예외 규칙은 만들지 않는다.
5. 지우는 규칙은 보수적으로(애매하면 남김), 잇는 규칙도 보수적으로(애매하면 끊음).

| 단계 | 규칙 | 문제 | 상태 |

| A 문자 | W1~W3, C1, C2 문자 정리 | 보이지 않는 문자 | 유지 |
| | (결정 시) K1 한국어 가짜 띄어쓰기 지우기(1차 `fake_spaces`) | 띄어쓰기 | 설계 |
| B 문서 | G1 깨진 문서 제외 | | 유지 |
| C 나누기 | B1 숨은 문단 경계에서 나눔 | 덜 나뉨 | 시험 완료 |
| D 잡음 지우기 | **G4 [새] 그림 영역 안 글 블록 지우기**(블록 영역의 50% 넘게 그림 영역 안, 캡션 제외) | 그림 글 | 설계 |

남겨 두는 것(한계로 기록): 표 병합 칸 중복, Docling 읽기 순서 오류 중 보정 패턴 밖의 것, 수식 모델의 미세 오인식(`sim`→`sin`), 증명 제목·알고리즘 줄 같은 정상 반복, 짧은 목록 항목.

### 3.1 출력 형식
`processed_para/<데이터셋>/<doc_id>.json` = `src/rag/units.py` `para_record` 형식
`{doc_id, dataset, lang, title, fmt, source, n_pages, n_units, n_tokens, log, units: [{text, kind, heading, pages, block_ids, n_tokens}]}`
+ `processed_para/_manifest.json`: 규칙 목록·버전, 규칙별 합계(적용 건수·지운 단어 수), 제외 문서, 코드 커밋, 생성 시각.

## 4. 검증 절차 (표본 → 전체)
1. **남은 문제 지표**(`residual.py`): 위 1.2 표의 항목이 줄어드는지. 목표: 참고문헌 남은 문서 10→2편 이하, 그림 영역 글 0, arXiv 도장 0, 낱글자 단어 대부분 제거.
2. **지운 것 검증**: 규칙마다 지운 블록 20개를 무작위로 뽑아 원본 쪽 이미지와 대조. 본문을 지운 것이 1개라도 나오면 규칙 수정.
3. **이은 것 검증**: L1·P1·Q2 이은 곳 표본 각 20개.
4. **QA 근거 보존**: QA 정답·근거 글이 `processed_para`에 남아 있는 비율(지운 규칙 때문에 사라진 QA가 있는지). 가장 중요.
5. 표본에서 통과하면 1차 전체 실행(PDF 1,042편 + docx 95편, 약 8~10시간) → 2차 → 같은 검증을 전체에 → `src/`로 옮김.

## 5. 결정 필요
1. 한국어 가짜 띄어쓰기 수정(1차 표시 + 2차 K1)을 넣을지
2. docx 양식 항목 붙이기(S2)를 넣을지
3. 반복 머리말 H2의 기준값(20%, 퍼지 90)을 Marker 기본값 그대로 쓸지
