# 프로젝트 2-1 연구계획

DIP Challenge Lab 학부연구 프로젝트

## 1. 문제 정의

LLM은 한 번에 처리할 수 있는 토큰 수에 한계가 있다. 흩어진 수십 개의
.docx 파일이나 타임스탬프가 포함된 대용량 자막 파일을 단순히 글자 수로
자르면 문장 중간에서 끊겨 문맥이 손실된다.

텍스트를 의미 단위(semantic boundary)로 분할하고, 처리(번역/요약) 후
다시 병합하는 자동화 Python 파이프라인을 구축한다.

핵심 질문: 단순 글자수 분할과 의미 기반 분할이 최종 결과
(요약 품질, 번역 자연스러움)에 어떤 영향을 미치는가?

## 2. 데이터셋

| 데이터 | 형식 | 역할 |
|---|---|---|
| OpenSubtitles 자막 | .srt | 대화체, 전처리(타임스탬프 제거) 실습 |
| 강의자료, 자체 제작 문서 | .docx | 설명문, 주제 전환 검증, 병합 시나리오 |
| LongBench | HF Datasets | 긴 문서 QA, 검색 정확도 정량 평가 |

자막과 문서는 문체와 문장 길이가 달라, 데이터 종류별로 청킹 결과가
어떻게 달라지는지 비교할 수 있다.

## 3. 방법론

### 3.1 비교 대상

- 단순 글자수 분할: 오프셋 슬라이싱. 문장 경계를 무시한다.
- 의미 기반 분할: 인접 문장의 임베딩 코사인 유사도로 경계를 탐지한다.


### 3.2 의미 기반 분할 알고리즘

문장 분리 → 임베딩 → 코사인 유사도 계산 → 경계 탐지 → 분할

유사도가 임계값보다 낮은 지점을 주제 전환으로 보고 자른다.
임계값은 고정값, percentile, 표준편차(std) 세 방식을 지원한다.

### 3.3 임베딩 모델: bge-m3

후보였던 Qwen3-Embedding-4B는 서버의 transformers 버전 제약으로
로드가 불가능했다. bge-m3는 약 1GB로 LLM과 동시 로드 시 여유가 있고,
처리 속도가 빨라 어블레이션 실행 횟수 측면에서도 유리하다.
선정 근거 상세는 서베이 노트 참조.

### 3.4 평가

#### 검색 기반 정량 평가 (top-k)

청킹 결과를 벡터화하고, 질문과의 코사인 유사도로 상위 k개 청크를
검색한다. 검색된 청크에 정답이 포함되면 성공으로 간주해 정확도를 낸다.

  질문 → 청크 검색(top-k) → 정답 포함 여부 → 정확도 %

LongBench의 (context, input, answers) 구조를 그대로 활용한다.
두 청킹 방식에 동일한 검색기와 동일한 k를 적용하므로,
정확도 차이는 청킹 품질의 차이로 해석할 수 있다.

k는 어블레이션 변수로 두어 검색 개수가 결과에 미치는
영향도 함께 측정한다.

#### 생성 품질 평가

- 정량: 평가지표(ROUGE 등)로 품질 수치화
- 정성: 자연스러움과 정보 보존을 사람이 비교

bge-m3(약 1GB)와 경량 LLM(약 6GB)을 동시에 올려도 여유가 있어
현재 계획상 Tier 2는 불필요하다.
